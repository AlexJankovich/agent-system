# LLM Adapter — функциональное описание

## Назначение

LLM Adapter — единственная точка контакта бота с языковой моделью.
Он получает от Bot Core запрос на генерацию ответа, обращается к модели
и возвращает сгенерированный текст.

Bot Core не знает, какая именно модель используется и где она
размещена. LLM Adapter скрывает эти детали за единым поведением:
«дан запрос — получен ответ».

## Ответственность

- Принимает от Bot Core запрос на генерацию ответа.
- Формирует обращение к модели в понятном ей виде.
- Получает текст ответа от модели.
- Возвращает текст ответа в Bot Core вместе с информацией о том,
  какая модель отвечала.
- Соблюдает ограничение по времени ожидания ответа.
- Сообщает Bot Core о сбое, если модель недоступна или вернула ошибку.

## Что НЕ делает

- Не общается с пользователем и не знает, из какого канала пришёл запрос
  (эта информация может передаваться как контекст, но не влияет на способ
  взаимодействия с моделью).
- Не решает, нужно ли отвечать пользователю.
- Не разбивает ответ на части и не доставляет его.
- Не хранит историю диалога.
- Не знает деталей конкретного канала.

## Вход и выход (по смыслу)

| Направление | Что приходит / уходит |
|---|---|
| Из Bot Core | Текст запроса; при необходимости — системная инструкция |
| В модель | Обращение в формате, понятном модели |
| Из модели | Сгенерированный текст (или сигнал о сбое) |
| В Bot Core | Текст ответа и сведения о модели |
| В журнал | Модель, длительность, объём запроса и ответа, результат |

## Сценарии

1. **Обычный запрос.** Bot Core передаёт текст → LLM Adapter обращается
   к модели → возвращает ответ.
2. **Системная инструкция.** Если в конфигурации задана общая инструкция
   для модели, она добавляется к каждому запросу.
3. **Модель не отвечает вовремя.** Ожидание прерывается; в Bot Core
   возвращается сигнал о сбое.
4. **Модель вернула ошибку.** В Bot Core возвращается сигнал о сбое
   с описанием причины для журнала.
5. **Модель вернула пустой ответ.** Это также считается сбоем и
   передаётся в Bot Core.

## Границы v1

- Одновременно активна **одна** модель; выбор — через конфигурацию.
- Поддерживается один способ обращения к модели — единый для
  локальных и удалённых решений.
- Ответ формируется целиком; постепенная выдача не поддерживается.
- Расширенные возможности модели (инструменты, вложения, режимы)
  не используются.

## Расширения

Пока нет. Файлы расширений размещаются в `docs/{module}/extensions/`
(см. `docs/README.md` §7). Примеры будущих расширений:

- **MCP** (`mcp.md`) — подключение внешних инструментов.
- **RAG** (`rag.md`) — дополнение запроса фрагментами
  из внешнего хранилища знаний.
- **Стриминг** (`llm-streaming.md`) — постепенная выдача.
- **Мультимодельность** (`llm-multi-model.md`) — маршрутизация.
