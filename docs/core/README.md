# Bot Core — функциональное описание

## Назначение

Bot Core — центральный блок бота. Он получает сообщения от Adapter Layer,
принимает решение о том, как на них реагировать, обращается к LLM Adapter
за генерацией ответа и передаёт результат обратно в Adapter Layer.

Bot Core не знает, из какого сервиса пришло сообщение и какая модель
формирует ответ. Он работает с обоими соседями как с взаимозаменяемыми
блоками.

## Ответственность

- Получает от Adapter Layer каждое новое сообщение пользователя.
- Проверяет, нужно ли на сообщение отвечать, и приводит его к виду,
  пригодному для передачи модели.
- Запрашивает у LLM Adapter сгенерированный ответ.
- Передаёт готовый ответ в Adapter Layer для доставки пользователю.
- Разбивает длинный ответ на части, допустимые в канале.
- Реагирует на сбои соседних блоков, не завершая работу бота.
- Ведёт структурированный журнал обработки каждого сообщения.

## Что НЕ делает

- Не общается с внешним сервисом напрямую.
- Не вызывает языковую модель по сети.
- Не формирует текст ответа самостоятельно.
- Не хранит историю диалога.
- Не знает деталей конкретного канала и конкретной модели.

## Вход и выход (по смыслу)

| Направление | Что приходит / уходит |
|---|---|
| Из Adapter Layer | Сообщение пользователя в едином виде |
| В LLM Adapter | Запрос на генерацию ответа |
| Из LLM Adapter | Сгенерированный текст (или сигнал о сбое) |
| В Adapter Layer | Готовый текст ответа и адресат (возможно, частями) |
| В журнал | Запись об обработке: канал, пользователь, длительность, результат |

## Сценарии

1. **Обычное сообщение.** Пришло сообщение → проверка → запрос к модели →
   ответ доставлен пользователю.
2. **Пустое или нетекстовое сообщение.** Сообщение игнорируется,
   модель не вызывается, пользователь ничего не получает.
3. **Слишком длинное входящее сообщение.** Текст усекается до
   допустимого размера, затем обрабатывается как обычно.
4. **Модель не отвечает вовремя.** Запрос к модели прерывается,
   пользователю уходит понятное сообщение о временной недоступности,
   сбой фиксируется в журнале.
5. **Модель вернула ошибку.** Поведение такое же, как при таймауте:
   пользователь получает сообщение о недоступности, сбой логируется.
6. **Модель вернула пустой ответ.** Пользователю уходит сообщение
   о том, что ответ не был сформирован.
7. **Длинный ответ модели.** Ответ разбивается на части в пределах
   допустимой длины канала и доставляется пользователю последовательно.
8. **Сбой отправки ответа в канал.** Факт фиксируется в журнале;
   повторная отправка в v1 не выполняется.

## Границы v1

- Обрабатывается одно сообщение за раз в рамках одного диалога;
  состояния между сообщениями нет.
- Правила реакции на сообщение минимальны: отвечаем на любой
  непустой текст.
- Разбиение длинного ответа выполняется по размеру, без учёта
  структуры текста.

## Расширения

Пока нет. Файлы расширений размещаются в `docs/{module}/extensions/`
(см. `docs/README.md` §7). Примеры будущих расширений:

- правила фильтрации сообщений (`core-filters.md`),
- сохранение и использование истории диалога (`core-history.md`),
- маршрутизация между несколькими моделями (`core-routing.md`),
- режим постепенной выдачи ответа (`core-streaming.md`).
