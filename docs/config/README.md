# Config — функциональное описание

## Назначение

Config — единая точка, через которую все модули бота получают свои
настройки. Он читает источник конфигурации, проверяет её на
соответствие ожиданиям и отдаёт модулю готовый набор значений.
Если конфигурация не соответствует ожиданиям, модуль не запускается.

## Ответственность

- Принимает от модуля запрос на загрузку конфигурации.
- Читает источник конфигурации (файл окружения или переменные).
- Проверяет прочитанное на соответствие схеме.
- Возвращает модулю набор значений, приведённый к нужным типам.
- Сообщает об ошибке, если конфигурация не соответствует схеме.
- Пишет в лог факт загрузки и причину отказа.

## Что НЕ делает

- Не хранит конфигурацию после возврата — модуль держит её у себя.
- Не перечитывает конфигурацию во время работы процесса.
- Не следит за изменениями источника.
- Не сливает значения из нескольких источников с приоритетами.
- Не хранит дефолты внутри себя — они заданы схемой.
- Не знает, что именно настраивается — смысл полей определяет
  модуль-потребитель.

## Вход и выход (по смыслу)

| Направление | Что приходит / уходит |
|---|---|
| От вызывающего кода | Запрос на загрузку |
| Из источника | Значения конфигурации |
| В вызывающий код | Набор значений, приведённый к типам, или ошибка |
| В журнал | Факт загрузки, уровень логирования, причина отказа |

## Сценарии

1. **Успешная загрузка.** Модуль запрашивает конфигурацию →
   Config читает источник → проверяет по схеме → возвращает
   готовый набор.
2. **Отсутствие обязательного поля.** Config обнаруживает, что
   поле не задано → возвращает ошибку с указанием поля.
3. **Неверный тип или значение.** Config обнаруживает, что поле
   задано, но не соответствует допустимым значениям → возвращает
   ошибку с указанием поля и допустимых значений.
4. **Дефолтное значение.** Поле не задано, но имеет дефолт →
   Config подставляет дефолт, ошибки нет.
5. **Ошибка чтения источника.** Источник недоступен → Config
   возвращает ошибку с причиной.

## Границы v1

- Один источник: файл окружения и переменные окружения.
- Загрузка выполняется **один раз** при старте процесса.
- Схема конфигурации описана в пакете `contracts`; Config только
  применяет её.
- Если конфигурация невалидна — процесс завершается с кодом 1.
- Логирование факта загрузки — на уровне `info`; ошибки — `error`.

## Расширения

Пока нет. Файлы расширений размещаются в `docs/{module}/extensions/`
(см. `docs/README.md` §7). Примеры будущих расширений:

- **Файл конфигурации** (`config-file.md`) — чтение из JSON/YAML-файла
  вместо переменных окружения.
- **Горячая перезагрузка** (`config-reload.md`) — перечитывание
  по сигналу.
- **Несколько источников** (`config-sources.md`) — слияние с
  приоритетами.
- **Секреты из внешнего хранилища** (`config-secrets.md`) — Vault,
  AWS Secrets Manager.
