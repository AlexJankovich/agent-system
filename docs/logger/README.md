# Logger — функциональное описание

## Назначение

Logger — единый способ, которым все модули бота записывают события
своей работы. Он принимает сообщение и произвольный набор полей,
приводит их к общему виду и выводит в стандартный поток.

Logger — это библиотека, а не отдельный процесс. Каждый модуль,
который что-то делает, использует Logger у себя. Кто и как собирает
и хранит вывод — за пределами модуля.

## Ответственность

- Принимает от модуля текстовое сообщение и произвольный набор
  дополнительных полей.
- Отбрасывает записи, уровень которых ниже настроенного.
- Приводит запись к единому формату, пригодному для машинной
  обработки.
- Выводит запись в стандартный поток вывода (stdout). Запись
в поток ошибок (stderr), файл или сеть не выполняется.
- Позволяет создавать производные логгеры, к которым добавлен
  общий контекст.

## Что НЕ делает

- Не читает конфигурацию сам — уровень и имя процесса передаются
  при создании.
- Не агрегирует записи из разных процессов.
- Не хранит записи на диске и не отправляет их по сети.
- Не фильтрует секреты и персональные данные из полей.
- Не создаёт глобальный логгер сам по себе — сколько логгеров
  создано и с каким контекстом, решает вызывающий модуль.

## Вход и выход (по смыслу)

| Направление | Что приходит / уходит |
|---|---|
| От модуля | Сообщение, уровень, контекст (пары ключ-значение) |
| От вызывающего кода при создании | Имя процесса, минимальный уровень |
| В стандартный поток | Одна строка на запись, пригодная для машинного разбора |

## Сценарии

1. **Обычная запись.** Модуль вызывает метод нужного уровня →
   Logger проверяет уровень → формирует запись → выводит её.
2. **Запись ниже уровня.** Модуль вызывает метод, уровень которого
   ниже настроенного → запись отбрасывается, ничего не выводится.
3. **Запись с контекстом.** Модуль добавляет к записи набор полей
   (идентификатор чата, длительность и так далее) → поля попадают
   в запись рядом с сообщением.
4. **Производный логгер.** Модуль создаёт от существующего логгера
   производный, добавив общий контекст (например, идентификатор
   задачи) → все последующие записи производного логгера содержат
   этот контекст; исходный логгер не меняется.
5. **Ошибка в контексте.** Модуль передаёт объект-ошибку как одно
   из полей → Logger разворачивает её в читаемый вид (имя, текст,
   стек).
6. **Несериализуемое значение.** В контексте оказывается значение, 
   которое нельзя представить напрямую (циклическая ссылка,
   слишком большое число, Infinity, NaN) → Logger выводит
   запись, заменяя проблемное значение на понятную пометку;
   сам Logger не падает.

## Границы v1

- Logger — **библиотека**, а не отдельный процесс; каждый модуль
  пишет в свой стандартный поток.
- Поддерживаются четыре уровня: `debug`, `info`, `warn`, `error`.
- Формат вывода — **одна машиночитаемая строка на запись**, без
  выравнивания и оформления для человека.
- Вывод идёт **только** в стандартный поток; записи в файл или
  по сети не выполняется.
- Поля контекста передаются как есть; фильтрация секретов
  не выполняется. Объекты-ошибки разворачиваются в читаемый
  вид на любом уровне вложенности.
- Глобального логгера нет: каждый модуль сам создаёт свой
  экземпляр при старте.

## Расширения

Пока нет. Файлы расширений размещаются в `docs/{module}/extensions/`
(см. `docs/README.md` §7). Примеры будущих расширений:

- **Человекочитаемый вывод** (`logger-pretty.md`) — оформление
  для локальной разработки.
- **Отдельный процесс-агрегатор** (`logger-process.md`) — сбор
  записей из всех процессов в одно место.
- **Фильтрация секретов** (`logger-redaction.md`) — удаление
  чувствительных полей перед выводом.
- **Файловый приёмник** (`logger-file-sink.md`) — запись в файл
  с ротацией.
- **Прореживание** (`logger-sampling.md`) — ограничение частоты
  повторяющихся записей.
